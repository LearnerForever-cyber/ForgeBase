# Core Principles

## Context

Forgebase is not just a toolset — it is a way of thinking about systems. These principles guide every design and architectural choice. Understanding them is essential before exploring architecture, guides, or examples.

## When to Use This

- **First read if:** You're new to Forgebase or evaluating whether it fits your philosophy
- **Reference if:** You're making design decisions and need to align with Forgebase values
- **Skip if:** You already know what Forgebase stands for and want to dive into implementation

---

## 1. Clarity Over Cleverness

If something is hard to explain, it is likely poorly designed.

Forgebase prefers:
- Readable over compact
- Explicit over implicit
- Obvious over impressive

---

## 2. Docs Are the Product

Documentation is not support material.  
It *is* the product.

Every feature must:
- Be explainable
- Have a clear mental model
- Fit naturally into the documentation structure

---

## 3. Systems Should Teach

Using Forgebase should improve a developer’s understanding of systems.

Users should leave with:
- Better intuition
- Transferable knowledge
- Confidence to build independently

---

## 4. Minimalism With Direction

Forgebase avoids:
- Feature bloat
- Premature abstraction
- Tool-first thinking

Minimalism is applied with a clear long-term direction.

---

## 5. Evolution Over Reinvention

Systems are allowed to grow, but not reset casually.

Every change should:
- Respect existing mental models
- Extend rather than replace
- Remain backward understandable

---

## 6. Calm Software

Forgebase aims to feel:
- Quiet
- Stable
- Trustworthy
